01 / Contexto

O problema de negócio

Em um negócio SaaS, entender quais clientes estão perdendo engajamento é importante para orientar ações de retenção. Mas antes de classificar risco, é necessário definir corretamente os clientes, as unidades, os pedidos e o significado de cada indicador.

O trabalho foi realizado para uma empresa real e envolveu organizar fontes operacionais, revisar as regras dos indicadores existentes e desenvolver uma aplicação multipágina que apresenta análises de negócio. A solução foi entregue ao gestor, com remuneração prevista pelo trabalho.

02 / A solução entregue

Aplicação analítica multipágina

Desenvolvimento de uma aplicação web para análise de clientes, comportamento, retenção e receita de uma empresa SaaS voltada ao setor de restaurantes. O trabalho foi entregue ao gestor e reúne estruturação em Python, interface Streamlit e consultas ao PostgreSQL.

O que o sistema contempla

Visão executiva, clientes em risco, Cliente 360, oportunidades de relacionamento, comercial, retenção preventiva, geografia da carteira, receita, cancelamentos históricos e inteligência de churn.

04 / Decisões importantes

Confiabilidade antes de um score

Definir o grão

Um identificador técnico de pedido não deve ser confundido com um número operacional exibido em diferentes contextos. Junções precisam respeitar chaves verificadas.

Evitar receita incorreta

Valores de pedido, mensalidade contratual, cobrança e receita recorrente não são automaticamente equivalentes.

Respeitar o tempo

Uma fotografia antiga da base pode apoiar testes históricos, mas não deve ser exibida como retrato atual dos clientes.

Não inventar probabilidades

Um índice de risco baseado em regras não equivale a uma probabilidade estatística calibrada de churn.

06 / Entrega e limites de validação

O que está estruturado e o que falta

O projeto foi desenvolvido para uma empresa real e a aplicação multipágina foi entregue ao gestor. O repositório contém organização por camadas, documentação de arquitetura, consultas de investigação, controles de acesso somente leitura, testes e interface Streamlit. Parte das definições financeiras e dos indicadores ainda depende de reconciliação com regras de negócio e com o BI de referência.

O marco de entrega ao gestor já foi realizado. Para mostrar visualmente a solução no portfólio, a próxima evolução será incluir capturas autorizadas ou demonstração com dados sintéticos. A implantação definitiva em produção e a homologação integral dos indicadores não foram confirmadas.

Capturas das páginas

As imagens originais das telas ainda não foram recuperadas. A apresentação já documenta os dez módulos da aplicação; capturas autorizadas poderão ser adicionadas sem divulgar dados de clientes.

Transparência: esta página descreve decisões e aprendizados técnicos, não comprova uma previsão de churn em produção, redução efetiva de cancelamentos ou acurácia de modelo. O repositório original é privado; não são divulgados dados, configurações ou código corporativo.
